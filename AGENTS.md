# Правила для AI-агентов (Claude Code, Codex и другие)

Ты работаешь над Roblox-игрой **Marshrutka 13: Don't Let Them On**. Команда:
- **Ринат** — владелец проекта, тестирует в Studio, мержит PR.
- **Оркестратор** (отдельный Claude) — продумывает игру, ставит задачи, ревьюит PR, владеет контрактами.
- **Claude Code** и **Codex** — пишут код параллельно, каждый в своих модулях.

## Прочитай перед работой

1. `docs/GDD.md` — что за игра.
2. `docs/ARCHITECTURE.md` — структура, владельцы модулей, контракт ремоутов, правила безопасности.
3. `docs/TASKS.md` — найди свою задачу (CC = Claude Code, CX = Codex).

## Железные правила

1. **Трогай только свои файлы** (владельцы в ARCHITECTURE.md). Чужой модуль не правим,
   даже если «быстро поправить». Нужна правка — пиши в PR, раздел «Нужно от других».
2. **Контракты не меняй**: `src/shared/Remotes.luau`, `src/shared/Config.luau`,
   `src/shared/AnomalyTypes.luau`, всё в `docs/`. Нужно изменение — раздел PR
   «Нужно изменить контракт» с точным предложением. Исключение: в `Config.luau` можно
   поправить значения баланса в PR с объяснением.
3. **Не редактируй `docs/TASKS.md`** — статусы ведёт оркестратор.
4. **Одна задача = одна ветка = один PR.** Ветка: `cc/T02-route` или `cx/T03-driver`.
   Не коммить в `main` напрямую.
5. **Сервер не доверяет клиенту.** Каждый `OnServerEvent` проверяет тип и диапазон аргументов,
   роль игрока, дистанцию и кулдаун. Деньги начисляет только сервер.
6. **Никогда не ставь на модели пассажиров атрибут, который выдаёт аномалию** (`IsAnomaly` и т.п.).
7. Числа баланса и тайминги — только из `Config`. Не хардкодь.
8. Луау: `--!strict`, `task.*` вместо `wait/spawn/delay`, без `while true` без ожидания.
9. Пиши так, чтобы игра работала **на телефоне**: крупные кнопки, UI в Scale, мало частиц.

## Отчёты оркестратору — issue #24

Оркестратор не видит ваши чаты. Поэтому **каждый ответ, который важен для оркестратора**, дублируйте
коротким комментарием в issue #24 («Журнал агентов»):
`gh api repos/Shikitoafk/marshrutka-13-don-t-let-them-on/issues/24/comments -f body="..."`
Первая строка — **[CC]** или **[CX]**, номер задачи и суть. Пишите: открыл PR (номер + 2–3 строки),
результаты проверки в Studio через MCP (Output, что видно, баги), вопросы к оркестратору.

## Roblox Studio MCP (если подключён)

Через MCP можно **смотреть и проверять**: дерево Workspace, запуск Play, чтение Output, скриншоты, временные
проверки через выполнение кода. **Нельзя** через MCP править скрипты или навсегда менять карту: скрипты живут
в файлах `src/` и Rojo перезапишет правки из Studio; всё постоянное — только через файлы и PR.
Перед каждым действием через MCP Ринат видит запрос — описывай коротко, что и зачем делаешь.

## Как проверить свою работу

- `rojo build -o build.rbxlx` должен собираться без ошибок (если Rojo установлен).
- Если MCP Studio не подключён, ты не можешь запустить Studio. В любом случае в PR **обязательно** напиши Ринату
  пошаговый тест: что нажать в Studio и что он должен увидеть.
- Если задача зависит от модуля, которого ещё нет, — сделай заглушку внутри **своего** модуля
  и напиши об этом в PR.
